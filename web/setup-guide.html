Local setup guide · no secrets included

Set up JournalEdge safely, from zero to live.

Follow the steps in order. This guide configures the public marketing home, secure app, Supabase control plane, Cloudflare Worker API, encrypted R2 journal vault, OAuth providers, and deployment domains.

Security ruleNever paste passwords, access tokens, service-role keys, wallet keys, or the R2 encryption secret into chat, Git, HTML, or browser code. Use the provider secret stores described below.
01

Install prerequisites

Use Node.js, Git, Supabase CLI, and Wrangler on the development machine.

node --version npm --version git --version npx supabase --version npx wrangler --version
02

Install project dependencies

Install the web client and Worker packages separately.

cd web npm install npm run typecheck npm run build cd ../backend/worker npm install npm run typecheck npm test
03

Create the Supabase project

Supabase stores identity, profiles, settings, roles, billing metadata, and audit records—not raw private journals.

1. Create projectCreate a project at supabase.com and copy the project URL and public anon key.
2. Apply migrationsRun both SQL migrations in order from backend/supabase/migrations.
3. Enable RLSConfirm all public tables show Row Level Security enabled.
4. Add first adminGrant the admin role only from a trusted SQL session.
insert into public.user_roles (user_id, role) values ('AUTH_USER_UUID', 'admin') on conflict (user_id, role) do nothing;
04

Enable account providers

Configure the providers displayed on the account screen.

GoogleEnable Google OAuth and add the callback URL for /app.html.
AppleConfigure Apple Services ID, key, team ID, and callback.
MicrosoftEnable Azure provider and add the JournalEdge redirect URL.
GitHubCreate an OAuth app and add the Supabase callback URL.
TelegramRequires a verified bot authorization endpoint. Do not put the bot secret in Vite variables.
Email/passwordEnable email confirmation and password recovery templates.
05

Create the Cloudflare R2 vault

Create the private bucket for encrypted trade and journal objects.

npx wrangler login npx wrangler r2 bucket create journaledge-vault npx wrangler r2 bucket list
Bucketjournaledge-vault
Object boundaryusers/{userId}/vault/trades.json
EncryptionWorker AES-GCM envelope encryption with a secret 32-byte key.
Browser accessNo public bucket. Access only through authenticated Worker routes.
06

Create Worker secrets

Set secrets through Wrangler. These values must never be committed.

cd backend/worker npx wrangler secret put SUPABASE_URL npx wrangler secret put SUPABASE_ANON_KEY npx wrangler secret put VAULT_ENCRYPTION_KEY # Generate a 32-byte base64 key with a trusted local tool. # Store it in your password manager after creation.
Do not use the service-role key in the browser.The Worker may use server secrets when required; the React build may only contain the public Supabase anon key.
07

Configure local environment

These public client variables select the Supabase project; they do not replace Worker secrets.

VITE_API_BASE_URL
VITE_SUPABASE_URL
VITE_SUPABASE_ANON_KEY
VITE_TELEGRAM_AUTH_URL

Use a local .env file only. The repository ignores .env files; never add them to Git.

08

Run and verify locally

Run the public home, app, preview, and Worker together.

# Terminal 1 cd web npm run dev -- --host 127.0.0.1 # Terminal 2 cd backend/worker npx wrangler dev --local --port 8787 --ip 127.0.0.1

Local previewhttp://127.0.0.1:5173/preview-all-pages.html
Worker healthhttp://127.0.0.1:8787/health
09

Deploy the Worker and Pages app

Deploy the API first, then the static frontend with the production environment variables.

# Deploy API cd backend/worker npx wrangler deploy # Build frontend cd ../../web npm run build # Deploy the web/dist directory through Cloudflare Pages or CI
Build outputweb/dist contains index.html, marketing.html, app.html, assets, manifest, robots, and service worker.
Preview safetyThe all-pages preview is local-only and is intentionally excluded from production Vite inputs.
10

Connect domains and perform launch checks

Make the marketing site public and keep the app/admin routes protected.

Marketinghttps://learngermanwith.fun/ → public home

Admin apphttps://admin.learngermanwith.fun/app.html?area=admin → role protected
