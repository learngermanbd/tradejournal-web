Beginner-friendly DNS instructions

Connect JournalEdge to your Cloudflare domain.

This guide tells you which records to use for the marketing website, user app, admin app, and backend API. Cloudflare may create some records automatically.

Open Cloudflare
ImportantDo not delete existing MX, SPF, DKIM, DMARC, or domain-verification records. They may be needed for email and ownership verification. Do not paste API tokens or passwords into this guide.

01 · Before you start

Complete these first.

  1. Your domain nameservers point to Cloudflare.
  2. Your Cloudflare Pages project is connected to GitHub.
  3. Your Pages project builds with npm run build from the web directory.
  4. Your Worker is deployed separately as journaledge-api.
Marketing websitelearngermanwith.fun
User applicationapp.learngermanwith.fun
Admin applicationadmin.learngermanwith.fun
Backend APIapi.learngermanwith.fun

02 · Connect the website to Cloudflare Pages

Use the automatic method first. It is safer than typing records manually.

  1. Open Workers & Pages in Cloudflare.
  2. Open your Pages project.
  3. Choose Custom domains → Set up a custom domain.
  4. Add each of these domains:
Website partDomain to addWhat it does
Marketinglearngermanwith.funPublic homepage
User appapp.learngermanwith.funLogin and user dashboard
Admin appadmin.learngermanwith.funProtected admin dashboard

Cloudflare should create the DNS records automatically. If it asks you for a manual record, use the Pages target shown in your dashboard.

TypeNameTargetStatus
CNAME@Proxied
CNAMEappProxied
CNAMEadminProxied
CNAME @ YOUR-PAGES-PROJECT.pages.dev CNAME app YOUR-PAGES-PROJECT.pages.dev CNAME admin YOUR-PAGES-PROJECT.pages.dev

03 · Connect the Worker API

Do not connect R2 directly to the browser. The Worker is the secure bridge.

  1. Open Workers & Pages → journaledge-api → Settings → Domains & Routes.
  2. Choose Add Custom Domain.
  3. Enter api.learngermanwith.fun.
  4. Let Cloudflare create the DNS record and SSL certificate.

If Cloudflare requires a manual record, use the exact Worker hostname shown after deployment.

CNAME api YOUR-WORKER-SUBDOMAIN.workers.dev
Do not create DNS for R2The R2 bucket stays private and is accessed only by the Worker.
Do not create DNS for SupabaseUse the Supabase project URL in environment variables.

04 · What you should not add

These services do not need public DNS records.

ServiceDNS record needed?Correct setup
Cloudflare R2NoKeep the bucket private.
SupabaseNoUse the project URL and anon key in settings.
GitHubNoConnect it inside Cloudflare Pages.
EmailDo not change existing recordsKeep current MX, SPF, DKIM, and DMARC records.

05 · Final check

DNS may take a few minutes to update. Then open each address.

Open marketing websiteOpen user appOpen admin appCheck API health
RememberDNS only connects addresses. It does not create the Pages project, deploy the Worker, create Supabase tables, or add environment variables.
