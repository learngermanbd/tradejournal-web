Beginner-friendly instructions

Set up JournalEdge without getting lost.

Follow one step at a time. First test the website on your computer. Only after that, connect Supabase and Cloudflare to put it online.

The simple order

1. Test locally → 2. Create accounts → 3. Connect Supabase → 4. Connect Cloudflare → 5. Add your domains.

Only want to see the app?Do Steps 1 and 2. You do not need cloud accounts or secret keys yet.
Important safety ruleNever paste passwords, service-role keys, Cloudflare API tokens, Telegram bot secrets, or the R2 encryption key into this guide, GitHub, or browser code.
01

Understand the five services

You do not need to build five separate websites. Each service has one job.

GitHub = code storageStores the project code: github.com/learngermanbd/tradejournal-web
Cloudflare Pages = websiteShows the marketing website, user app, and admin app online.
Cloudflare Workers = backendRuns the secure server API called journaledge-api.
Cloudflare R2 = trade storageStores encrypted trades, notes, psychology, and attachments.
Supabase = login databaseHandles login, users, settings, roles, and subscriptions.
Domains = website addressesMarketing: learngermanwith.fun · App: app.learngermanwith.fun · Admin: admin.learngermanwith.fun
02

Run the website on your computer

Start here. This lets you review the design before connecting any cloud service.

Open a terminal inside the project folder.

Run the frontend command first. If you also want to test the backend, open a second terminal window.

cd web npm install npm run dev -- --host 127.0.0.1
Open marketing websiteOpen the appOpen login
Optional: start the backend too
cd backend/worker npm install npx wrangler dev --local --port 8787 --ip 127.0.0.1

Backend health check: http://127.0.0.1:8787/health

03

Test the demo accounts

Demo accounts are only for local testing. They do not save real cloud data.

Demo userEmail: demo.user@journaledge.local

Demo adminEmail: demo.admin@journaledge.local
Password: DemoAdmin123!

Open the login page from Step 2. Click the Demo user or Demo admin button. These buttons disappear from production builds.

04

Create your Supabase project

Do this when you are ready for real user accounts and cloud settings.

  1. Open supabase.com and create a project.
  2. Copy the project URL and public anon key.
  3. In the Supabase SQL Editor, run these two files from the project:
First migrationbackend/supabase/migrations/001_control_plane.sql
Second migrationbackend/supabase/migrations/002_product_control_plane.sql

Turn on Google, Apple, Microsoft, and GitHub inside Supabase Authentication only when you are ready. Telegram needs its own verified bot setup.

Admin access — do this only after creating your real account

Get the user ID of your real account, then run this in Supabase SQL Editor:

insert into public.user_roles (user_id, role) values ('YOUR_REAL_USER_ID', 'admin') on conflict (user_id, role) do nothing;
05

Create Cloudflare storage and backend

Cloudflare Pages hosts the website. Workers runs the backend. R2 stores private journal data.

  1. Open dash.cloudflare.com and create or select your account.
  2. Create an R2 bucket named journaledge-vault.
  3. In backend/worker/wrangler.toml, keep the JOURNAL_VAULT binding.
  4. Log in from a terminal:
cd backend/worker npx wrangler login npx wrangler r2 bucket create journaledge-vault npx wrangler deploy
Worker secrets — only after you understand the setup

Enter each value when Wrangler asks. These secrets must never be committed to GitHub:

npx wrangler secret put SUPABASE_URL npx wrangler secret put SUPABASE_ANON_KEY npx wrangler secret put VAULT_ENCRYPTION_KEY
06

Publish the website with Cloudflare Pages

Connect GitHub to Cloudflare Pages so every approved change can build the website.

  1. In Cloudflare, open Workers & Pages and choose Create application → Pages → Connect to Git.
  2. Select the repository learngermanbd/tradejournal-web.
  3. Use these build settings:
Root directoryweb
Build commandnpm run build
Output directorydist
Node versionUse the current LTS Node version.

Add the public frontend values in Cloudflare Pages environment variables: VITE_API_BASE_URL, VITE_SUPABASE_URL, and VITE_SUPABASE_ANON_KEY. Never add the R2 encryption key there.

07

Connect the three domains

Do this last, after the website and backend work on the Cloudflare preview URL.

Public marketing websitelearngermanwith.fun
User applicationapp.learngermanwith.fun
Admin applicationadmin.learngermanwith.fun
  1. In Cloudflare Pages, open Custom domains.
  2. Add each domain and follow the DNS instructions.
  3. Set the Worker API URL in the frontend environment variables.
  4. Test login, demo removal, trade protection, R2 access, and admin role protection.
You are finished when:

The marketing page opens publicly, the app requires login, the admin area requires an admin role, and private journal data never appears in public pages or advertising requests.
