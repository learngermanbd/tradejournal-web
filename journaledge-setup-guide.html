Set up the actual JournalEdge stack.

This is the real deployment plan for the current repository: GitHub source, Cloudflare Pages frontend, Cloudflare Workers API, Cloudflare R2 encrypted journal storage, Supabase Auth/Postgres control plane, and the three active domains.

Security boundaryNever place passwords, Supabase service-role keys, Cloudflare API tokens, Telegram bot secrets, or the R2 encryption key in this HTML file, chat, browser code, or Git. Use Supabase secrets, Wrangler secrets, and Cloudflare Pages environment variables.
01

Know the hosting and resource map

These are the services currently selected for JournalEdge. Railway and Render are not used by the current implementation.

Source control · GitHubRepository: github.com/learngermanbd/tradejournal-web
Frontend · Cloudflare PagesBuild from web/dist. Public marketing home is the root domain.
Backend · Cloudflare WorkersWorker name: journaledge-api. API routes handle auth, trades, settings, quotes, and admin metrics.
Private storage · Cloudflare R2Bucket binding: JOURNAL_VAULT. Bucket name: journaledge-vault.
Control plane · SupabaseAuth and PostgreSQL store profiles, settings, roles, subscriptions, feature flags, sync metadata, and audit data.
Active site areasMarketing root, user app subdomain, and protected admin subdomain. Community is removed from the active site.

03

Create Supabase and apply the control plane

Supabase is not the raw private journal store. It is the identity and metadata database.

Create projectCreate a Supabase project and record its URL plus public anon key.
Apply SQLRun 001_control_plane.sql, then 002_product_control_plane.sql in the SQL editor or CLI.
Verify RLSProfiles, roles, subscriptions, sync metadata, audit logs, and service events must have RLS enabled.
Create userSign up one real account through the app, then use its UUID for the admin role.
insert into public.user_roles (user_id, role) values ('AUTH_USER_UUID', 'admin') on conflict (user_id, role) do nothing;
04

Configure Google and other account providers

Provider buttons exist in the app login screen, but each provider must be enabled in Supabase first.

GoogleEnable Google and configure the provider client ID/secret in Supabase.
AppleConfigure Apple Services ID, key, team ID, and redirect configuration.
MicrosoftEnable Supabase Azure provider and configure the Microsoft app registration.
GitHubCreate a GitHub OAuth app and use Supabase's callback URL.
TelegramUse a separately deployed, verified bot authorization endpoint and set VITE_TELEGRAM_AUTH_URL. Never expose the bot secret.
Redirect allowlistAllow https://app.learngermanwith.fun/app.html and the local http://127.0.0.1:5173/app.html URL in Supabase Auth.
05

Create the private R2 journal vault

Cloudflare R2 stores encrypted trade records and future attachments.

npx wrangler login npx wrangler r2 bucket create journaledge-vault npx wrangler r2 bucket list
BindingJOURNAL_VAULT in backend/worker/wrangler.toml.
Object keyusers/{userId}/vault/trades.json.
EncryptionWorker AES-GCM envelope encryption with a private 32-byte key.
AccessNo public bucket. Only authenticated Worker routes can read or write.
06

Configure Worker secrets

These belong in Wrangler's secret store, not in GitHub or Vite.

cd backend/worker npx wrangler secret put SUPABASE_URL npx wrangler secret put SUPABASE_ANON_KEY npx wrangler secret put VAULT_ENCRYPTION_KEY # VAULT_ENCRYPTION_KEY must decode to exactly 32 bytes. # Keep it in a password manager and recovery procedure.
ImportantSUPABASE_ANON_KEY is public client configuration. Supabase service-role keys, Cloudflare API tokens, and the vault key are server-only and must never be placed in VITE_ variables.
07

Configure local frontend variables

Create a local web/.env file. It is ignored by Git and is not the Worker secret store.

VITE_API_BASE_URL
VITE_SUPABASE_URL
VITE_SUPABASE_ANON_KEY
VITE_TELEGRAM_AUTH_URL

The local demo user and demo admin buttons work without cloud credentials. They are in-memory only and removed from production builds.

09

Deploy the API and frontend

The current production hosting is Cloudflare Workers plus Cloudflare Pages. No Railway or Render service is required.

# Deploy the API cd backend/worker npx wrangler deploy # Build the web artifact cd ../../web npm run build # Cloudflare Pages settings # Root directory: web # Build command: npm run build # Output directory: dist
